# Particle System Notes

These notes describe the particle formats and viewer behavior currently implemented in the web particle viewer and compound model viewer.

## Source Formats

The XML dump contains particle data in several forms:

```text
Modern .pte.xml files with ParticleSystemParameters
Legacy .pte.xml files with Particle Event / particle1.Def
Unified particle XML generated by particle_xml_unify.py
Compound .cmp.xml files referencing or embedding .pte particle parts
```

The original files are binary UTF containers. The `.xml` files are the human-readable dump of those containers.

## Modern ParticleSystemParameters

Modern particle files contain a binary `ParticleSystemParameters` block. Important fields decoded by the viewer include:

```text
pspFlags
colorFrames[32]
colorKeyFrameBits
textureName
textureFps
srcBlend
dstBlend
gravity
emitterDirection
emitterNozzleSize
emitterNozzleDamp
initialParticleCount
maxParticleCount
lifetime
frequency
particleLifetime
particlePositionRandomizer
particleVelocity
particleVelocityRandomizer
particleTwistVelocity
particleSize
particleSizeVelocity
boundingSphereRadius
```

Color frames are always kept, even when not keyed. The key bitmask says which frames are authored keys, but the full frame array is still useful as baked/interpolated color data and preserves round-trip information.

## Legacy Particle Event Format

Older files use:

```text
Particle Event
  particle1.Def
```

The viewer converts the legacy event definition into the same internal parameter shape used by modern particles.

Legacy fields include:

```text
alpha
alphaDecay
color
colorVelocity
frequency
gravity
lifetime
maxParticles
nozzle
nozzleDamp
initial particle count
particle life
random position
size
size velocity
texture name
twist speed
velocity
velocity randomizer
blend mode
optional extended gravity/fog/life flags
optional color frame table
```

## Unified XML

`particle_xml_unify.py` converts modern and legacy `.pte.xml` files into a common XML representation.

Typical usage:

```powershell
python particle_xml_unify.py xml_dump --out-dir xml_unified --recursive
```

The unified format keeps original particle semantics but exposes them as normalized XML fields. This is intended as a bridge toward future Godot import work.

## Compound Particle Parts

Compound files can include particle parts in the `Cmpnd` part list. If a `.pte` part is referenced but not embedded, the model viewer attempts to load:

```text
../xml_dump/<particle-file>.xml
```

This allows examples such as `mblast.cmp.xml` to render their referenced particle effect when served from the local HTTP server.

Particle parts are attached through the same compound hierarchy as mesh parts, so their transforms follow the compound joint tree.

## Viewer Approximation

The Three.js viewer renders particles as point sprites. The implementation is a practical preview, not a pixel-perfect clone of the original Direct3D renderer.

Implemented behavior:

```text
particle spawning
initial particle count
max particle count
emitter direction/nozzle randomization
position randomization
velocity and velocity randomization
gravity
twist velocity approximation
particle size and size velocity
particle lifetime
color frame interpolation
texture lookup from UTF textures
fallback radial particle texture
basic blend mode mapping
```

The preview is close enough for visual identification and iteration, but some original render states, exact particle integration details, and editor-only behavior are approximated.
