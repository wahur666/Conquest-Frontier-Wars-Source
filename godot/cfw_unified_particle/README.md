# CFW Unified Particle Player

`CFWUnifiedParticlePlayer` renders converted Conquest: Frontier Wars `.pte` particle effects in Godot from the unified XML files generated by `particle_xml_unify.py`.

The player does not use Godot's built-in particle editor/runtime. The built-in emitter cannot represent the legacy format accurately enough because the legacy effect data includes embedded palette textures, 32 color frames, Direct3D blend modes, custom spawn behavior, and CPU-side billboard rendering. The scene tree is intentionally small:

```text
CFWUnifiedParticlePlayer
  Particles (MultiMeshInstance3D)
```

## Basic Use

1. Instance `res://cfw_unified_particle/CFWUnifiedParticlePlayer.tscn`.
2. Set `unified_xml_file` to a converted effect, for example:

```text
res://xml_unified/smissile.pte.unified.xml
```

3. Keep `preview_running` enabled for editor/runtime preview.
4. Use `restart_preview` to restart the effect without reloading XML.
5. Use `reload_preview` after changing the XML path or source XML content.
6. Use `save_xml` to write current inspector-tuned values back to XML. Leave `save_xml_file` empty to overwrite the loaded XML, or set it to a different path to save a variant.

The player parses the XML, decodes the embedded BMP texture from `embeddedImages`, creates a quad `MultiMesh`, and updates all particle instances in `_process`.

The implementation is split by responsibility:

- `CFWUnifiedParticlePlayer.gd`: simulation, spawning, billboard rendering, material setup, and inspector controls.
- `CFWUnifiedParticleXml.gd`: unified XML parsing, authoring metadata, numeric formatting, and XML save/write.
- `CFWParticleTextureDecoder.gd`: embedded BMP decoding and old texture-library fallback decoding.

## Runtime Model

Particles are CPU simulated and rendered as textured quads in a `MultiMeshInstance3D`.

- `world_scale` scales legacy position, velocity, and gravity units into Godot space.
- `size_scale` scales legacy particle sizes into Godot quad size.
- `random_seed` makes spawn randomness repeatable.
- `max_preview_particles` clamps generated particle capacity.
- `billboard_mode` controls quad orientation. `Camera Facing` is the default.
- `end_behavior` controls how the Godot preview/runtime decides an effect has ended.
- `zero_particle_lifetime_seconds` can give source particles with lifetime `0` a practical authored lifetime for drain-to-finish previews.

For effects where XML `maxParticleCount` is `0`, capacity is estimated from `frequency * particle_lifetime`.

## XML Parameters

After loading XML, the parsed values are exposed in inspector groups. Runtime uses these exposed values, so they can be edited for tuning.

Use `apply_inspector_values` after editing exposed XML parameters to rebuild the material/MultiMesh and restart the effect.

Use the `Authoring` controls to preserve tuning decisions:

- `end_behavior`: `Legacy Source` keeps the converted values as-is, `Stop At Emitter End` clears particles when a finite emitter ends, and `Drain Particles` waits for spawned particles to expire.
- `zero_particle_lifetime_seconds`: Used when source `particle_lifetime` is `0`. Set this when you want `Drain Particles` to finish for effects whose legacy particles were marked as forever-lived.
- `save_xml_file`: Optional output path for a tuned XML variant.
- `save_xml`: Writes the current inspector values and authoring metadata to XML while preserving the existing embedded asset section.

### XML Rendering

- `render_texture_name`: Texture name referenced by the effect.
- `render_texture_fps`: Legacy animated texture FPS field. Not implemented yet.
- `render_src_blend`: Legacy Direct3D source blend value.
- `render_dst_blend`: Legacy Direct3D destination blend value.
- `render_bounding_sphere_radius`: Source bounding radius.
- `decoded_texture_size`: Decoded embedded texture dimensions.
- `embedded_texture_count`: Number of embedded texture entries found.

Blend mode support currently distinguishes additive `ONE, ONE` from normal mixed blending.

### XML Emitter

- `emitter_initial_particle_count`: Burst count at restart.
- `emitter_max_particle_count`: Legacy maximum count. `0` means estimate capacity.
- `emitter_lifetime`: Emitter duration. `0` means continuous emitter.
- `emitter_frequency`: Spawn rate per second.
- `emitter_nozzle_size`: Direction/nozzle spread influence.
- `emitter_direction`: Base emission direction.
- `emitter_nozzle_damp`: Randomized direction dampening.

### XML Particles

- `particle_lifetime`: Per-particle lifetime.
- `particle_position_randomizer`: Random spawn position offset.
- `particle_velocity`: Base particle speed.
- `particle_velocity_randomizer`: Velocity randomization multiplier.
- `particle_twist_velocity`: Rotates particle direction over time.
- `particle_size`: Initial quad size.
- `particle_size_velocity`: Size delta per second.
- `particle_gravity`: Acceleration applied to particle direction.
- `color_frames`: 32 legacy color/alpha frames used over particle life.

For additive effects with zero alpha color frames, the renderer treats alpha as visible so legacy `ONE, ONE` effects do not disappear.

## Debug Options

Debug options are off by default.

- `debug_trace`: Prints parser/render lifecycle logs.
- `debug_force_visible`: Writes a magenta fallback quad if no particles are visible.
- `show_cpu_particles`: Toggles the actual custom renderer.

The camera test scene has its own helper toggles:

- `show_center_marker`
- `show_ground`

Both are off by default to avoid helper geometry interfering with particle review.

## Test Scene

`CFWParticleCameraTest.tscn` is a small viewer scene with an orbit camera. Instance or place a `CFWUnifiedParticlePlayer` at the center and test in-game camera behavior.

Controls:

- Right mouse drag: orbit
- Middle mouse drag: pan
- Mouse wheel: zoom
- `F`: refocus target to origin

## Current Scope

Implemented:

- Unified `.pte.unified.xml` loading
- Embedded BMP texture decoding
- CPU spawn/update
- Color frame interpolation
- Additive blend alpha fallback
- Camera-facing billboards
- Inspector exposure for parsed XML fields

Not implemented yet:

- Animated texture pages via `render_texture_fps`
- Deeper flag behavior mapping
- Shield effects
- Compound/CMP effects
- Model-attached hardpoint particle binding
- Animation-driven effects
